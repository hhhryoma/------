# WBS と進捗管理の手順

設計書から WBS の下書きを作り、ガントチャートの進捗管理票で実績を記入し、毎週の進捗・完了見込み・週次報告を出すまでの流れです。ツールごとの細かい説明は、[ツールの README](../tools/README.md) にあります。

## 全体の流れ

| いつ | やること | 使うもの |
| --- | --- | --- |
| 計画 | [1. WBS の下書きを作る](#1-wbs-の下書きを作る) | New-WbsDraft.ps1 |
| 計画 | [2. 下書きを直して、進捗管理票にする](#2-下書きを直して進捗管理票にする) | Excel（進捗管理票） |
| 毎日 | [3. 実績を記入する](#3-実績を記入する毎日遅くとも週に-1-回) | Excel（進捗管理票） |
| 毎週 | [4. 進捗と完了見込みを見る](#4-進捗と完了見込みを見る毎週) | Measure-Progress.ps1 |
| 毎週 | [5. 週次報告を作る](#5-週次報告を作る毎週) | New-WeeklyReport.ps1（「送る」→「週次報告」） |
| 毎週 | [6. 工数を確かめる](#6-工数を確かめる毎週) | Measure-Effort.ps1 |
| 遅れたとき | [7. 遅れたとき](#7-遅れたとき) | 進捗管理票の見込終了・Measure-Progress.ps1 `-FillTemplate` |

## 0. 準備

- **休日の CSV**: 内閣府の「国民の祝日」の CSV（`syukujitsu.csv`）をそのまま使えます。会社の休日（年末年始・夏季休暇など）は、同じ形（1 列目が日付）で行を足してください。指定しないと、土日だけを休みにします
- **担当者**: 担当者の名前を決めておきます。兼務の人は稼働率を付けます（`佐藤:50%`。その人のタスクの日数が 2 倍になります）
- **工程の配分**: 工程（詳細設計・レビュー・製造・単体テストなど）と、その配分の割合です。既定は `tools\wbs\工程の配分.csv` です。社内の標準に合わせて写して直し、`-Phases` で指定します（[工程の配分の列](../tools/README.md#new-wbsdraftps1)）
- **フォルダ**: 毎日記入する進捗管理票と、設定ファイルを 1 つのフォルダに置きます。元の WBS や結果のブックは、別のフォルダに置きます（進捗・週次報告のツールは、フォルダの中のブックをすべて WBS として読むため）

```
D:\PJ\
  進捗管理票.xlsx        ← 毎日記入する
  syukujitsu.csv         ← 休日
  週次報告の設定.csv     ← 週次報告の設定（5.）
  週次報告\              ← 週次報告の出力
D:\PJ_計画\
  WBS_下書き.xlsx        ← 元の WBS（進捗管理票と同じフォルダに置かない）
```

## 1. WBS の下書きを作る

設計書の規模を数え、機能（画面・テーブル・IF など）ごとの工数を工程に配分し、担当者と予定日を決めた WBS の下書きを作ります。

```powershell
.\New-WbsDraft.ps1 D:\設計書 -Start 2026-12-01 -Members 山田, 佐藤, 鈴木:50% -Holidays D:\PJ\syukujitsu.csv -OutXlsx D:\PJ_計画\WBS_下書き.xlsx -Gantt
```

- 機能の工程は同じ担当者です。**レビューは作った人以外**に割り当て、**製造はレビューが終わってから**始めます。製造では**テーブルを先に**作り、画面などはテーブルの製造が終わってから始めます（工程の配分の「先に作る種類」）
- 会議・プロジェクト管理・環境の準備などの共通のタスクは、`-CommonTasks` で足せます（ひな形: `tools\wbs\共通のタスク_ひな形.csv`。時期は 全体・最初・最後）
- 工数が 1 人日に満たない機能（テーブルなど）は、同じ種類をまとめて 1 つのタスクにします（`M_CUSTOMER 顧客マスタ ほか 1 件`）
- 「先行」の列に、同じ機能の前の工程の WBS 番号が入ります（完了見込みの計算に使います）
- `-Gantt` を付けると、WBS のシートがそのまま**ガントチャートの進捗管理票**になります。付けないと、ふつうの表の WBS になります
- ブックには、担当者別（稼働率・工数の合計・期間）・規模（機能ごとの見積もりの根拠）・休日・**説明**（使い方・列の意味・バーの色）のシートも入ります

画面に表示される「完了予定」と担当者ごとの期間を見て、人数・開始日を決めます（[New-WbsDraft の説明](../tools/README.md#new-wbsdraftps1)）。

## 2. 下書きを直して、進捗管理票にする

下書きのままでは足りないところを、Excel で直します。

| 直すところ | 直し方 |
| --- | --- |
| 機能をまたいだ順番（画面どうしの順番など。テーブルの製造の後に画面の製造は、既定で入っています） | 「先行」の列に、先に終わっていないといけないタスクの WBS 番号を書き足す（`1.1, 2.3`。親の番号ならその下のすべて） |
| 会議・プロジェクト管理・環境構築などの共通のタスク | 下書きを作るときに `-CommonTasks` で足す。あとからなら、行を挿入して足す（WBS 番号・タスク名・担当者・予定開始・予定終了・予定工数） |
| 担当者の得意な機能・予定日 | 担当者・予定開始・予定終了を書き換える |
| 結合テストなど、前の工程がすべて終わってから始める工程 | 工程の配分の「待ち合わせ」を `する` にして作り直す |

- `-Gantt` で作った WBS は、そのまま進捗管理票として使います。ファイル名を `進捗管理票.xlsx` などにして、案件のフォルダに置きます
- ふつうの表の WBS（社内の雛形の WBS も）からは、Measure-Progress.ps1 で進捗管理票を作ります。元の WBS は、案件のフォルダから別のフォルダに移してください

```powershell
.\Measure-Progress.ps1 D:\PJ_計画\WBS.xlsx -Holidays D:\PJ\syukujitsu.csv -OutGantt D:\PJ\進捗管理票.xlsx
```

進捗管理票の列・バーの色は、ブックの「説明」シートにもあります（[進捗管理票の説明](../tools/README.md#ガントチャートの進捗管理票を作る-outgantt)）。

## 3. 実績を記入する（毎日、遅くとも週に 1 回）

| 記入するもの | いつ |
| --- | --- |
| 実績開始 | 作業を始めたとき |
| 進捗率（0〜100%） | 毎日・毎週 |
| 実績終了 | 作業が終わったとき（記入すると完了。進捗率 100% でも完了） |
| 見込終了 | 遅れそうなとき（終わりそうな日。予定終了の後ろに見込みの延び（赤）が描かれる） |
| 実績工数 | 日報で工数を管理していなければ、かかった工数（人日） |

- **状態**（完了・遅延・未着手・予定どおり）と**バー**は、数式と条件付き書式で自動で変わります。状態の列には記入しません
- 基準日（右上）は開いた日です。報告日に合わせたいときは、日付に書き換えます
- タスクを足すときは、行を挿入して、上の行の「状態」の数式をコピーします。WBS 番号・先行は文字のまま入ります（`2.10` が `2.1` になりません）
- 休日が増えたら、「休日」シートに日付を足します

## 4. 進捗と完了見込みを見る（毎週）

```powershell
.\Measure-Progress.ps1 D:\PJ\進捗管理票.xlsx -Holidays D:\PJ\syukujitsu.csv -OutXlsx D:\PJ_計画\進捗\進捗_20261106.xlsx
```

```
タスク 26 件（2026/11/06 時点。親のタスクは除く）: 完了 14・遅延 8・予定どおり 0・未着手 4
PV 12.98 / EV 7.66 / BAC 20.1 / SPI 0.59
遅延 8 件（最大 4 営業日: SCR001 受注一覧（詳細設計））
完了見込み: 2026/11/19（予定の 2026/11/13 より 4 営業日遅れ）
  予定終了より遅れる見込みのタスク 12 件（うち 4 件は、まだ遅れていないが、先行タスク・同じ担当者の前のタスクの遅れで後ろにずれるもの）
  完了見込みを決めている流れ: 1.1 SCR001 受注一覧（詳細設計）（山田） → … → 4.3 SCR003 受注詳細（単体テスト）（山田）
```

（設計書のサンプルの WBS で、担当 3 人のうち山田さんの SCR001 の詳細設計が 11/06 に 70% のままの例です）

| 見るところ | 意味 |
| --- | --- |
| 遅延 | 営業日で 1 日以上遅れているタスク（遅れの大きい順） |
| SPI | 予定に対して、どれだけ進んでいるか（1 未満なら遅れ） |
| **完了見込み** | 遅れを、先行タスクと同じ担当者の後のタスクに送ったときの、全体の終わる日 |
| 完了見込みを決めている流れ | 全体の終わりを遅らせているタスクのつながり（最初のタスクが、もとの遅れ） |
| まだ遅れていないがずれるもの | 前のタスクの遅れで、これから遅れるタスク（先に手を打てる） |

`-OutXlsx` の結果のブックには、タスクごとの見込開始・見込終了と、**予定・実績と完了見込みを並べたガントチャート**（見込みの延びは赤）が入ります。報告の資料にそのまま使えます（[完了見込みの説明](../tools/README.md#完了見込み)）。

## 5. 週次報告を作る（毎週）

案件のフォルダに `tools\weekly-report\週次報告の設定_ひな形.csv` を `週次報告の設定.csv` の名前で写し、WBS（進捗管理票）・指摘管理表・障害管理表などの場所を書いておきます。

```
項目,値
WBS,進捗管理票.xlsx
休日,syukujitsu.csv
実績,週次報告\実績.csv
基準日,金曜日
```

毎週、案件のフォルダを右クリックして「送る」→「週次報告」を選ぶか、次のコマンドで作ります。

```powershell
.\New-WeeklyReport.ps1 D:\PJ
```

- 報告の文章（メールやチャットに貼る）・担当者ごとのリマインド・Excel の報告ができます
- 進捗には、タスクの状態・SPI・**完了見込み（前回との比較つき）**・今週の完了・遅延・来週の予定が載ります（[週次報告の説明](../tools/README.md#new-weeklyreportps1)）

## 6. 工数を確かめる（毎週）

日報・工数実績表で工数を管理しているときは、WBS の予定工数と比べて、予定を超えた・超えそうなタスクを見つけます。

```powershell
.\Measure-Effort.ps1 D:\PJ\日報 -Wbs D:\PJ\進捗管理票.xlsx -Holidays D:\PJ\syukujitsu.csv
```

週次報告の設定に「工数実績」を書くと、週次報告にも載ります（[工数の説明](../tools/README.md#measure-effortps1)）。

## 7. 遅れたとき

1. 遅れそうなタスクの**見込終了**を記入します。進捗管理票に見込みの延び（赤）が描かれ、Measure-Progress.ps1 の完了見込みにも入ります
2. **完了見込みを決めている流れ**を見て、全体の終わりを遅らせているタスク（担当者の偏り・待ち合わせ）を見つけ、担当者の入れ替え・先行の見直しを考えます
3. 大きく遅れたときは、遅延タスクと週ごとの完了数を、スケジュール遅延リカバリ計画のテンプレートに書き込み、リカバリ計画を作ります

```powershell
.\Measure-Progress.ps1 D:\PJ\進捗管理票.xlsx -Holidays D:\PJ\syukujitsu.csv -FillTemplate ..\docs\schedule-recovery\スケジュール遅延リカバリ計画_テンプレート.xlsx -OutFile D:\PJ_計画\リカバリ計画.xlsx
```

（[スケジュール遅延リカバリ計画](schedule-recovery/README.md)）

## よくある質問

| 困ったこと | 原因と対処 |
| --- | --- |
| 行を足したら、状態が出ない・バーが描かれない | 状態は数式です。上の行の「状態」のセルをコピーしてください。バーは予定開始・予定終了が日付なら描かれます |
| 「2.10」と入れたら「2.1」になった | 前に作った進捗管理票では、WBS 番号の列が数の書式のことがあります。`'2.10` のように先頭に `'` を付けて入れてください（今のツールで作った進捗管理票は文字の書式です） |
| 祝日が営業日として数えられている | 休日の CSV を `-Holidays`（週次報告は設定の「休日」）で指定し、進捗管理票の「休日」シートにも足してください |
| 「同じタスクが、いくつものファイルにあります」と出る | 元の WBS と進捗管理票を同じフォルダに置いています。元の WBS を別のフォルダに移してください |
| 完了見込みが思ったより遅い | 「完了見込みを決めている流れ」を見てください。同じ担当者のタスクは、予定でそのタスクの開始日までに終わるものを先に終えるとみなします（予定で重なっているタスクは並行）。先行の列の番号が違っていないかも確かめてください |
| 見込終了を書いたのに、状態が遅延にならない | 見込終了が予定終了より後で、基準日以降の日付のときだけ遅延です。基準日より前の見込終了は古いものとして使いません |
| LibreOffice で開くと、バーの色の重なりが違う | バーは Excel の条件付き書式で描いています。Excel で開いてください |
